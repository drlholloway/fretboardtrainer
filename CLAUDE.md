# Fretman (Fretboard Trainer)

iOS and Android app for learning the notes and chords on a guitar or bass
fretboard: quick multiple-choice drills plus a Duolingo-style learning path.
Product name **Fretman**, subtitle Fretboard Trainer; internal identifiers
(`fretboard_trainer` package, `dev.laneholloway.fretboard_trainer` bundle id,
`fretboardtrainer-*` release files) stay as they are.

Read `PLAN.md` first; it is the design and status. `CHANGELOG.md` is the
release history and becomes the GitHub release notes.

## Layout

Pub workspace, mirroring the Sightings (DC75Workbench) repo in the sibling
directory.

- `packages/fretboard_theory/` — pure Dart, no Flutter: pitches, tunings,
  instruments, chord shapes and naming, drill question generation, curriculum.
  Everything musical lives here and is unit tested.
- `apps/fretboard_trainer/` — Flutter app. Riverpod for state, go_router for
  navigation, shared_preferences for settings and progress. Only renders and
  stores; no music logic.
- `packaging/icon/make_icon.py` — draws the icon masters (Pillow).
- `packaging/appimage/`, `packaging/flatpak/`, `packaging/linux/` — Linux
  packaging, built only in CI (no Linux toolchain on the dev Mac).
- `docs/screenshots/` — rendered screens, regenerated by `just screenshots`.
  The wiki (`fretboardtrainer.wiki.git`, cloned separately) uses copies of
  them under `images/`; update both when a screen changes.

## Commands

```sh
dart pub get
just test          # theory tests + app widget tests
just analyze       # dart analyze + flutter analyze
just run-macos     # macOS is the dev target; opens in a phone-sized window
just screenshots   # re-render docs/screenshots (golden tests, macOS fonts)
just icons         # redraw the icon and regenerate every platform icon set
```

Without `just`: `dart test` in `packages/fretboard_theory`, `flutter test`
and `flutter run -d macos` in `apps/fretboard_trainer`. Shell PATH needs
`/opt/homebrew/bin` for `flutter` and `uv`.

Run `just analyze` and `just test` before finishing a change. After UI
changes run `just screenshots` and look at the PNGs; screen capture and the
VM-service screenshot do not work in this environment, and no iOS simulator
runtime is installed. Debug builds honor `FRETBOARD_ROUTE=/lesson/<id>` to
open a screen directly.

## Conventions

- American spelling in code, UI text, docs and commits.
- Strings are indexed from the lowest-pitched string (0); `stringNumber`
  gives the player's numbering. Fret 0 is the open string.
- Chords are named from their sounding pitches via `identifyChord`, never
  from a label. New shapes go into `ChordLibrary` as semitone-offset
  templates with a test pinning tab and name in standard tuning.
- Open shapes keep their fingering in uniformly transposed tunings and keep
  their pitches otherwise (E in drop D is `222100`). Movable shapes keep
  their intervals in every tuning.
- Lesson ids from `Curriculum` are stored in learner progress. Do not
  rename them without saying so in the changelog.
- Lessons always teach standard tuning first; only the final unit uses the
  drop tuning. The free drill uses whatever tuning is set.
- No telemetry, accounts or network calls. The tip link is the only URL.
- Painters take their base `TextStyle` from the theme so test renders use
  the loaded font; do not construct bare `TextStyle`s in `CustomPainter`s.

## Git and releases

- Commit only when asked. Push over SSH (the `gh` token lacks the
  `workflow` scope, so workflow-file changes cannot go over HTTPS).
- Dependabot PRs: merge when CI is green; an Android Gradle plugin bump
  needs the matching Gradle wrapper bump merged first.
- Release, same as Sightings: fold **Unreleased** in `CHANGELOG.md` into a
  dated `## X.Y.Z` section, bump `version:` in `apps/fretboard_trainer/pubspec.yaml`,
  commit `Release X.Y.Z`, `git tag -a vX.Y.Z -m "Fretman X.Y.Z"`, push
  branch and tag, and add a `<release>` line to the Flatpak metainfo. The
  `release` workflow builds the signed Android APK, an ad-hoc signed macOS
  zip and the Linux tarball / AppImage / Flatpak, and publishes the release
  with the changelog section as notes. iOS ships through TestFlight, not the Releases page.
- Android signing: `apps/fretboard_trainer/android/app/fretboardtrainer-release.jks`
  and `key.properties` next to it, both gitignored, mirrored in the repo
  secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
  `ANDROID_KEY_ALIAS` (`fretman`), `ANDROID_KEY_PASSWORD`. The keystore is
  PKCS12, so the key password equals the store password. Never regenerate it.
